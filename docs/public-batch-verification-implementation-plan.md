# Public Batch Verification Landing Page — Implementation Plan

## 1. Overview & Objective

When a consumer or retailer scans the QR code printed on any manufactured food jar or box (generated by our **Label Print Station** in the Admin Backoffice), their mobile camera resolves the opaque token URL:

```text
https://<store-domain>/verify/bv_RPK202609222965...
```

This plan outlines the architecture, UI/UX design, component breakdown, and security requirements to build the **Consumer-Facing Batch Verification Page** inside `apps/web` (Next.js App Router).

```
          [Printed Jar / Packaging Label]
                        │
                        ▼ (QR Code Scan via Smartphone Camera)
       https://<store-domain>/verify/[publicToken]
                        │
                        ▼
            Next.js Server Component (SSR)
         (apps/web/app/verify/[token]/page.tsx)
                        │
                        ▼ GET /api/v1/manufacturing/public/verify/:token
             Express API Backend
      (FinishedGoodsLotModel.findOne)
                        │
                        ▼
     ┌───────────────────────────────────────┐
     │      Public Verification Response     │
     │  - Authenticity Status (VERIFIED etc) │
     │  - Product & Variant Description      │
     │  - Batch / Lot Reference Number       │
     │  - Packed & Best-Before Expiry Dates  │
     │  - Ingredient Farm Origin Disclosures │
     │  - FSSAI License Number Verification  │
     │  (STRICTLY NO COGS / Margins / Prices)│
     └───────────────────────────────────────┘
```

---

## 2. Core Architectural Decisions

1. **Server-Side Rendered (SSR) for Instant Mobile Performance**:
   - Built as a **React Server Component** (`apps/web/app/verify/[token]/page.tsx`) to deliver near-instant First Contentful Paint (FCP) on mobile cellular connections without client-side data waterfall delays.
   - Generates dynamic OpenGraph metadata (`og:title`, `og:description`, `og:image`) so sharing the link on WhatsApp/iMessage shows an official authenticity preview.

2. **Security & Commercial Privacy Sandbox**:
   - The public endpoint (`GET /api/v1/manufacturing/public/verify/:publicToken`) already strictly sanitizes output.
   - Never exposes internal supplier IDs, vendor purchase costs, formulation percentages, or warehouse internal storage bins.

3. **Dynamic Safety Status Precedence**:
   The verification page renders distinct visual states based on the authoritative quality state:
   - 🟢 **`VERIFIED`**: Fresh batch, within shelf life, approved by QA.
   - 🔴 **`RECALLED`**: Emergency safety recall issued. Critical safety warning with instructions not to consume, emergency hotline, and refund steps.
   - 🟡 **`EXPIRED`**: Shelf life passed (`expiryDate <= now`). Best-before date warning.
   - ⚪ **`NOT_AVAILABLE_FOR_SALE`**: Lot is in quarantine or rejected by QC.
   - ❌ **`NOT_FOUND` (404)**: Invalid or unverified token. Renders counterfeit warning.

4. **Configurable Base URL for QR Codes**:
   - Update `apps/admin/src/components/manufacturing/print-label-modal.tsx` to read `process.env.NEXT_PUBLIC_STORE_URL` (with fallback to current origin) so that printed QR codes directly target the public storefront (`apps/web`) rather than the admin backoffice port.

## 3. UI/UX Design & Aesthetic Specifications (Mobile-First)

The page should impress consumers with transparency, craftsmanship, and safety:

### A. Header & Brand Seal
- Minimalist store header with brand logo.
- Animated holographic/shield authenticity badge ("Official Batch Verification").

### B. Hero Batch Status Card
- **VERIFIED State**:
  - Emerald green theme (`emerald-500` / `emerald-600`), soft glowing border.
  - Verified checkmark icon with subtle pulse animation.
  - "Authentic Artisan Kitchen Batch".
  - Shelf-Life Progress Gauge showing days remaining until best-before date.
- **RECALLED State**:
  - High-visibility red banner (`rose-600`), warning triangle.
  - "IMPORTANT FOOD SAFETY NOTICE: BATCH RECALLED".
  - Clear customer guidance: "Please do not consume. Contact support for an immediate replacement or full refund."
- **EXPIRED State**:
  - Amber badge (`amber-600`), "Best Before Date Passed".
  - Packed date vs Expiry date contrast.

### C. Batch Specifications Grid
- Clean 2-column or card layout:
  - **Product**: Title and high-resolution product imagery.
  - **Packaging**: Variant size (e.g. `250 g Glass Jar`).
  - **Batch / Lot #**: Monospace pill (e.g. `RPK-20260922-2965`).
  - **Packaging Date**: Formatted date (e.g. `September 22, 2026`).
  - **Best Before**: Formatted date (e.g. `October 31, 2026`).

### D. Farm Provenance & Sourcing Transparency
- Visual origin timeline:
  - Farm Partner / Region (e.g., "Guntur District - Single-Origin Guntur Chilli").
  - Process Method (e.g., "Cold-Pressed Sesame Oil - Traditional Stone Mill").
  - Food Safety Certification (FSSAI License `10022021000123`).

### E. Consumer Conversion & Reorder CTA
- "Enjoying this batch?"
- Direct button to the product page on the store (`/products/[slug]`) to reorder fresh jars from the next batch.

## 4. Proposed File Changes & Component Structure

### New Files to Create in `apps/web`:

1. **`apps/web/app/verify/[token]/page.tsx`**:
   - Server Component that fetches verification data using `@ecommers/api-client` or direct internal fetch to `API_URL/api/v1/manufacturing/public/verify/${token}`.
   - Handles 404s via Next.js `notFound()`.

2. **`apps/web/app/verify/[token]/loading.tsx`**:
   - High-fidelity skeleton loader matching the status card and specifications grid.

3. **`apps/web/app/verify/[token]/not-found.tsx`**:
   - Dedicated error screen for unverified tokens:
     - "Unrecognized Batch Token"
     - Anti-counterfeiting advisory.
     - Contact customer support button.

4. **`apps/web/components/verification/verification-hero.tsx`**:
   - Renders the dynamic status card (`VERIFIED`, `RECALLED`, `EXPIRED`).

5. **`apps/web/components/verification/batch-details.tsx`**:
   - Displays lot number, packed date, expiry date, and pack size.

6. **`apps/web/components/verification/ingredient-origins.tsx`**:
   - Displays farm provenance cards and FSSAI licensing badges.

### Files to Modify:

1. **`apps/admin/src/components/manufacturing/print-label-modal.tsx`**:
   - Ensure the generated QR URL points to `NEXT_PUBLIC_STORE_URL` (e.g., `http://localhost:3000` or production store URL) rather than `localhost:3001` (admin backoffice).

## 5. Implementation Steps

### Phase 1: Storefront Route & Server Fetching
1. Set up route `apps/web/app/verify/[token]/page.tsx`.
2. Connect to public API endpoint `GET /api/v1/manufacturing/public/verify/:token`.
3. Add robust error boundary and `not-found.tsx`.

### Phase 2: Design & Component Construction
1. Build `VerificationHero` with status badges, SVG animations, and shelf-life indicator.
2. Build `BatchDetails` specifications card with clean typography and layout.
3. Build `IngredientOrigins` showcasing sustainable farming and FSSAI compliance.
4. Add store conversion link allowing customers to reorder the item.

### Phase 3: QR Code URL Synchronization
1. Update `apps/admin/src/components/manufacturing/print-label-modal.tsx` to generate QR codes using the storefront domain.

## 6. Verification & Quality Assurance Plan

### Automated Checks
- Monorepo Typecheck: `pnpm --recursive typecheck`.
- Lint: `pnpm --recursive lint`.
- Web App Production Build: `pnpm --filter web build`.

### Manual / Browser Verification
1. Open Admin Backoffice $\to$ Manufacturing $\to$ Packaging Runs.
2. Click "Print Labels" on any batch to generate the label preview.
3. Copy the public verification URL or scan the QR code with a phone/browser emulator.
4. Verify all 4 states:
   - **Fresh batch**: Shows green `VERIFIED` badge with correct dates and origins.
   - **Recalled batch**: Trigger a test recall in Admin $\to$ verify red `RECALLED` alert displays.
   - **Expired batch**: Test with an expired date $\to$ verify `EXPIRED` badge displays.
   - **Invalid token**: Navigate to `/verify/bv_invalid_999` $\to$ verify 404 counterfeit warning displays.
5. Verify responsive layout on mobile viewport (375px - 430px iPhone width).
